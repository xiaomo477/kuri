## 修复新文章《Linux集群架构》不显示问题

**症状**：新文章 `source/_posts/Linux集群架构.md` 在站点上看不到，`hexo generate` 无报错。

**根因**：front-matter 第 4 行写成了 `tags:技术分享`（冒号后缺空格）。
YAML 中 `key: value` 必须有空格，否则整段 front-matter 不是合法映射，
js-yaml 抛错 → Hexo 只打 ERROR 日志并**静默跳过整篇文章**，构建仍返回成功。

**定位命令**（必须加 `--debug`）：
```bash
npx hexo generate --debug 2>&1 | grep -iE "error|warn"
```
输出：`ERROR Process failed: _posts/Linux集群架构.md`

**修复内容**：
1. `tags:技术分享` → `tags: 技术分享`（致命）
2. 2 处 U+2011 非断行连字符 → 普通连字符 `-`（LVS-NAT / LVS-DR）
3. `#### 4).dir` / `#### 5).dir` → 补空格 `#### 4). dir`

**验证**：`hexo clean && hexo generate --debug` 零 error/warn；
产物 `public/2026/09/17/Linux集群架构/index.html` 已生成，标签正常渲染。

**备份**：`.workbuddy/backup/Linux集群架构.md.bak-20260917-095622`

## 修复手机端整页横向溢出 + 代码块溢出（10:00 前后）

**症状**：手机访问时整页可左右拖动；超长代码行（如 curl 归档源检测命令）撑破版面。

**实测数据**（iPhone 15 模拟 393px，Edge + agent-browser）：
- 修复前：`document.scrollWidth = 1023`（溢出 630px），`.blog-main` 被撑到 1007px
- 修复后：`document.scrollWidth = 393` = 视口宽，`.blog-main` = 361px

**根因**：`@media (max-width: 900px)` 下 `.blog-container` 改为 `flex-direction: column`，
但 `.blog-main` 的 `flex: 1 1 0` 在纵向模式下约束的是高度不是宽度，
宽度失去约束后被 pre/表格的固有宽度一路撑爆（body 的 overflow-x:hidden 只是掩盖）。

**修改文件**：
1. `themes/kuri/source/css/style.css` 移动端媒体查询：`.blog-container` 改 `display: block`，
   sidebar/main 设 `width: auto; max-width: 100%`
2. 同文件：`.post-content pre` 加 `max-width: 100%; -webkit-overflow-scrolling: touch`；
   `.post-content table` 加 `display: block; overflow-x: auto`（宽表格块内滚动）
3. `themes/kuri/layout/layout.ejs` + `blog-layout.ejs`：viewport meta 去掉
   `maximum-scale=1.0, user-scalable=0`（恢复双指缩放，无障碍）

**验证**：hexo server + agent-browser 实测截图（桌面 1080 / 手机 393），
长命令在代码块内横向滚动，页面无整页滚动。`hexo generate` 零报错。

**坑位记录**：
- agent-browser 在本机用 `AGENT_BROWSER_EXECUTABLE_PATH` 指向 Edge（Chrome 内核下载被墙）。
  守护进程不稳定：页面状态会在调用间被重置为 about:blank；`set viewport` 会清空页面；
  `set device` 必须在 `close --all` 后、`open` 前设置才能保持。
  页面 load 事件被 fonts.googleapis.com @import 挂起（该域名 TLS 被断），
  navigate 超时是正常的，文档其实已加载，直接 eval 即可。
- 截图 path 是位置参数：`agent-browser screenshot <path>`，不是 `--path`。
