## 修复两篇新文章无法生成的问题

**现象**：`hexo generate` 显示构建成功，但 `Linux服务器部署.md`、`Linux核心目录.md` 两篇文章的页面根本没生成，网站访问不到。

**报错日志**（加 `--debug` 才能看到）：
```
ERROR Process failed: _posts/Linux服务器部署.md
YAMLException: end of the stream or a document separator is expected (2:6)
```

**根因**：两篇文章的 front-matter 分隔符被写坏，开头多了一组 `---`，且分隔符行里混入了**零宽空格 U+200B**（看不见的字符，每个文件 2 个，分别在第 2 行和第 6/7 行）。js-yaml 解析到正文里的 `---` 就抛异常。

错误结构：
```
---
\u200b---      <- 多出来的分隔符 + 零宽空格
title: xxx
date: xxx
tags: xxxx
\u200b---
---
# 正文
```

**修复**：重写头部为标准格式，正文一字未动。原文件已备份到 `.workbuddy/backup/`。

**关键教训**：Hexo 遇到单篇 front-matter 解析失败**只会打 ERROR 日志并跳过该文章，不会中断构建**，所以表面上看"构建成功"。排查时要 `hexo generate --debug | grep -i error`。

- kuri 主题的 sidebar/模板完全没引用 `categories` 字段，写了也不生效（现有文章只有一篇带 categories）。
- 文件中存在 1 个 NO-BREAK SPACE (U+00A0)，位于 `Linux服务器部署.md` 的"注意事项总结"段落，不影响渲染，暂未处理。
